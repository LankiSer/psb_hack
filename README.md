# ПСБ Банк Docs

Юридический ассистент по кейсу Hack&Change 2026. Ищем ответы только по выданной базе, с цитатами. Учебный прототип, не банковский сервис.

## Быстрый запуск

**Сабмит (ZIP для платформы):**

```sh
git clone https://github.com/LankiSer/psb_hack.git
cd psb_hack
python scripts/build_submission.py
```

Загружай `dist/psb-submission.zip`. Внутри: `solution.py`, `psb_engine.py`, `psb_retrieval.py`, `rule_checks.py`, `requirements.txt`. Свой API-ключ для сабмита не нужен — платформа подставляет прокси сама.

**Веб локально:**

```sh
cp .env.example .env   # задай JWT_SECRET
docker compose up --build -d
```

Открой http://127.0.0.1:3000. Для локальной модели: Ollama + `ollama pull qwen3:4b` и `nomic-embed-text`. Без Docker — `./start-local.ps1` / `./stop-local.ps1`.

**Тесты и сборка:**

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/build_submission.py
```

## Как устроено

Next.js → FastAPI → общий `psb_engine.py` (поиск → генерация → проверка цитат). Тот же движок в вебе и в сабмите. Внешние законы не подключаем — только 21 учебный документ организаторов. Демовопросы в индекс не кладём.

В сабмите эмбеддинги с API платформы; в вебе — Ollama/Qdrant, при сбое остаётся лексический поиск. Реранкер по умолчанию выключен (`RAG_RERANK=0`).

Полезные переменные: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `DATA_DIR`, `MAX_WORKERS` (1–8), `RAG_QUERY_EXPANSION`, `RAG_SEMANTIC`, `RAG_TARGETED_REVIEW`.

Вход: CSV `id,question`. Выход: `submission.csv` (`id,answer`, до 10k символов). Общий дедлайн ~1100 с. Лимиты платформы: ZIP ≤128 МБ, 5 сабмитов/сутки.

## Честно

Локальная Qwen ≠ DeepSeek организаторов. Цитата ≠ правильный вывод. V8 дважды давал разный балл на одном коде — шум большой. Логов платформы нет, поэтому крутим по одному рычагу за сабмит.
