# ПСБ Банк Docs

Юридический ассистент по кейсу ПСБ / Hack&Change 2026. Только предоставленная база знаний: поиск положений, ответ с цитатами, просмотр исходного документа. Учебный прототип, не официальный банковский сервис.

## Быстро получить ZIP для сабмита

Нужен Python 3.12; для самой сборки зависимости не требуются.

```sh
git clone https://github.com/LankiSer/psb_hack.git
cd psb_hack
python scripts/build_submission.py
```

Загрузите **`dist/psb-submission.zip`** на платформу. Внутри ровно три файла в корне: `solution.py`, `psb_engine.py`, `requirements.txt`. Не архивируйте вручную `.venv`, `node_modules`, `.env` или весь рабочий каталог. После изменения кода повторите сборку. GitHub Actions также публикует ZIP в артефактах проверки.

## API организаторов — важное уточнение

**Собственный API-ключ для сабмита не нужен.** При автоматической проверке платформа передаёт адрес прокси и служебный ключ через переменные окружения. Отдельных ключей для локального использования организаторы не выдают. Локально можно использовать Ollama или собственный совместимый API. Финальный прототип должен работать с требуемой моделью; подключение предусмотрено, но доступ и качество на ней пока не проверены.

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL` / `OPENAI_BASE_URL` / `BASE_URL` | Адрес OpenAI-совместимого прокси |
| `LLM_API_KEY` / `OPENAI_API_KEY` | Служебный ключ платформы, автоматически |
| `LLM_MODEL` / `OPENAI_MODEL` / `GEN_MODEL` | Модель платформы; не зафиксирована в коде |
| `DATA_DIR` | Папка questions.csv и knowledge-base.zip; по умолчанию data |
| `MAX_WORKERS` | Параллелизм 1–8, по умолчанию 2 |

Поддерживаются имена архива `knowledge-base.zip`, `knowledge_base.zip`, `kb.zip`. Вход — UTF-8 CSV `id,question`, где question может содержать короткий диалог. Выход — `submission.csv` в рабочем каталоге с `id,answer`, одна запись на каждый исходный ID, до 10 000 символов. Контекст между ID не переносится. Есть общий срок 1100 секунд, чтобы успеть записать CSV до лимита 20 минут. При ошибке сервиса выводится явная техническая ошибка, а не выдуманный юридический ответ.

Ограничения платформы: ZIP до 128 МБ, 8 CPU / 16 ГБ RAM, 5 сабмитов в сутки (00:00 МСК). Мы не отправляем сабмиты автоматически.

## Веб-прототип

1. Скопируйте `.env.example` в `.env`, задайте случайный `JWT_SECRET`.
2. Для локальной модели установите Ollama и выполните `ollama pull qwen3:4b`. Либо заполните параметры своего совместимого API. Ключи не публикуйте.
3. Запустите:

```sh
docker compose up --build -d
```

Откройте http://127.0.0.1:3000, зарегистрируйтесь и перейдите к базе знаний. API: http://127.0.0.1:8000/docs. Порты 3000 и 8000 должны быть свободны. Остановка: `docker compose stop`. Учётные записи хранятся в отдельном Docker-томе. Docker Desktop на Windows обращается к локальной Ollama через host.docker.internal.

Без Docker: установите `backend/requirements.lock.txt`, из backend запустите `python -m uvicorn app.main:app --port 8000`; из frontend — `npm ci` и `npm run dev`. Параметры backend можно задать в backend/.env. Публичной главной нет: `/` ведёт во вход либо в базу знаний. Проекты, редактор, агент и загрузка личных документов исключены из режима кейса.

## Архитектура и проверка

Next.js → FastAPI с авторизацией → `psb_engine.py` → лексический поиск по фрагментам → генерация и адресное исправление некорректного формата → проверка ID и дословности цитат → документ с подсветкой строк. Один движок используется в веб-версии и сабмите. Эмбеддинги и реранкер необязательны и пока не подключены; внешние правовые источники не используются.

База содержит 21 учебный документ организаторов. Демовопросы и образцы ответов находятся отдельно и **не участвуют в поиске/генерации**.

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/build_submission.py
```

Frontend: `npx tsc --noEmit` и `npm run lint`. Проверка поиска: из backend `python scripts/verify_psb.py` с `PYTHONPATH=.`. GitHub Actions проверяет контракт ZIP/CSV и frontend; при этом модель не вызывается.

## Честные ограничения

Формат ZIP/CSV проверен из распакованного архива с тестовым генератором. Это не оценка качества модели. На локальной Qwen3 4B обнаружены ошибки в смысловых выводах: цитата сама по себе не доказывает корректность вывода. Платформа оценила первые две сборки в 18 и 17,417 балла; отчётов нет. Это не позволяет установить причину снижения или гарантировать результат новой сборки. Связанные редакции сохраняются в контексте; применимость по дате требует проверки моделью. История веб-чата пока существует только в текущей вкладке. Dockerfile подготовлены, полный образ ещё требует проверки сборки. Презентация финального этапа не входит в этот сабмит.

Логотип взят с официальной страницы фирменного стиля ПСБ: https://www.psbank.ru/bank/style. Никаких пользовательских документов, локальных баз, паролей и рабочих API-ключей в репозитории нет.

Аудит frontend отмечает уязвимости транзитивного PostCSS в ветке Next.js 15; обновление основной версии Next.js ещё не проведено. Пользовательские CSS и source maps приложение не принимает. Для публичного развёртывания требуется отдельная проверка зависимостей и инфраструктуры.

## Обновление v2 после первого сабмита (0,18)

Причина низкого балла неизвестна: платформа не предоставила логи. В v2 исправлены независимо воспроизводимые проблемы:
- корректный ответ больше не перезаписывается обязательным вторым вызовом;
- короткие ID источников S1/S2 преобразуются обратно в стабильные ID интерфейса;
- цитировать текст вручную необязательно: ID проверяется по реально найденному источнику, выдержку предоставляет приложение; поддельная переданная цитата по-прежнему отклоняется;
- неправильный формат/ссылки исправляются одним дополнительным вызовом;
- короткие договоры передаются целиком; ссылки на дополнительные соглашения ищутся по любому номеру договора;
- явно разбирается последняя реплика и уточнённый контрагент; обе редакции регламента доступны модели;
- увеличен запас выходных токенов, обрезанный ответ повторяется с большим бюджетом; ограничены сетевые повторы.

`python scripts/evaluate_local.py` прогоняет 18 демовопросов на локальной Qwen3 4B и сохраняет ответы в `dist/local-evaluation-v3.json`. Эталонные ответы не передаются генератору. Проверка наличия нужного документа даёт 17/17 и для v1, и для v2 (в одном вопросе основания нет), поэтому этот показатель не доказывает рост качества. Изменения проверяются отдельными контрактными и регрессионными тестами. Результат на скрытой выборке покажет только следующий сабмит; рост балла не гарантирован.

API/frontend проверяются без реальной модели: из backend `PYTHONPATH=. python scripts/verify_psb_api.py`. Контракт `answer/status/sources`, идентификаторы документов и подсветка строк сохранены.

## V3: исправления после результата 17,417

Изменения сделаны в общем движке веб-прототипа и сабмита:
- номера статей, включая короткие числа, участвуют в поиске; явно указанные статья и кодекс повышают приоритет соответствующего документа;
- поисковые сокращения НДС, НДФЛ и МРОТ раскрываются в термины, без добавления правовых фактов;
- короткие статьи передаются целиком, для длинных добавляются начало и соседние фрагменты; общий контекст ограничен 30 000 символов;
- новое указание контрагента перевешивает старый номер договора в истории; учитываются склонения многословных названий;
- отказ без единого источника заменяется нейтральным сообщением о недостатке данных, чтобы модель не добавляла выдуманные названия законов внутри отказа;
- модель получает только один ID каждого источника (S1 и т. д.), без конкурирующего внутреннего document_id;
- сообщения диагностики CSV-обработки содержат только ID вопроса, статус, число источников, время и тип ошибки. Вопросы, документы и ключи в stderr не печатаются.

Сборщик сохраняет рядом с ZIP файл `.build.json` с SHA-256 архива и исходников. Он не входит в ZIP. По нему можно отличить отправленные сборки.

Для адресной проверки: `python scripts/evaluate_local.py --ids 3,5,7,16 --output dist/recheck.json`.
Отчёт содержит исходный JSON модели для разбора ошибок и не включается в ZIP/Git. Проверки формата, поиска и совместимости API не заменяют оценку полноты и достоверности ответов. Повторная загрузка на платформу выполняется вручную.
