## 1. Что сделано

Цель V7 — поднять балл **без нового LLM-слоя** (уроки v4: лишние вызовы режут скор). Опора на ядро v6 + точечные правила вывода и запасной режим при нехватке времени.

### 1.1. Правки под известные провалы (#5, #9, #11, #13)

| Проблема | Что сделали |
|---|---|
| #5 — эхо вопроса при двух редакциях | SYSTEM: не повторять вопрос; по дате события выбирать редакцию и давать прямой вывод. `review_issues`: флаг «ответ = вопрос». |
| #9 — ложный `insufficient` (Альфа-Трейд / Трейдинг) | SYSTEM: при наличии договора с нужными условиями — `answer`, не отказ из‑за похожих имён. Review: `insufficient` + договорные фрагменты → одна перепроверка с разрешённым переходом в `answer`. |
| #11 — «да» при сроке выше лимита | SYSTEM: превышение «не более N» = «нет». `review_issues`: число в вопросе > лимита источника при утвердительном ответе. |
| #13 — выдуманные обязанности / чужие документы | SYSTEM: не тащить архив/регламент не по теме; не добавлять уведомления и т.п. без источника. Review: флаг выдуманного уведомления / «сразу удалить». |

### 1.2. Дедлайн без рандомного да/нет

При общем лимите 1100 с пайплайн сам урезается:

| Остаток времени | Режим | Поведение |
|---|---|---|
| > 70 с | `full` | plan + embeddings + review, до 180 с на вопрос |
| ≤ 70 с | `fast` | лексика + одна генерация, без plan/review/embeddings (~55 с) |
| ≤ 12 с / после сбоя | `deadline` | только найденные фрагменты, **без LLM**, без угадывания да/нет |

После таймаута `full` — один запасной `fast`, иначе `deadline`.

### 1.3. Реранкер

`RAG_RERANK` по умолчанию **0**: пост-v6 сборка с реранкером дала 27.746 < v6.

### 1.4. Проверки

- unit-тесты: **53/53 OK** (добавлены кейсы на эхо, лимит, порог одобрения, уведомление, ложный insufficient, fast/deadline).
- контракт ZIP/CSV сохранён: `solution.py`, `psb_engine.py`, `psb_retrieval.py`, `requirements.txt`.

- Прирост реальный: инфраструктура и формат уже давно не bottleneck.
- Плато ~30/100 значит: **поиск фрагментов почти насыщен**, судью режут **смысловые выводы** на скрытой выборке.
- V7 подтянул стиль/guardrails (+1.5), но не закрыл жёсткую логику «дата → редакция», «четыре ≠ 4», «не тот контрагент → отказ».
- Deadline-режим на прогоне ~600 с почти не включается; он страховка от нулей, не источник +30 баллов.

## 4. Мысли: как улучшать дальше

Приоритет — **детерминированная пост-логика и изоляция контекста**, не новый multi-agent и не оптимизация под локальную Qwen как под судью.

### 4.1. Highest ROI (следующий сабмит)

1. **Числа словами.** Сейчас лимит ловит `4`, но не «четыре» / «четырёх». Нужен словарь числительных → число, иначе #11-подобные кейсы снова проскочат.
2. **Не принимать плохой черновик.** Если после review ответ всё ещё эхо вопроса или «да» при превышении «не более N» — подменять шаблоном из источников (документ + пункт + вывод), а не оставлять сырой текст.
3. **Фильтр контекста по теме.** Вопрос про ПДн/ТК/налог — не подмешивать архив и регламент согласования. Контрагент: Трейд ≠ Трейдинг (якорь по полному/близкому имени).
4. **Выбор редакции по дате.** Если в вопросе есть месяц/год и в источниках две редакции порога — программно выбрать действующую на дату и сформировать короткий «да/нет + порог», даже если модель промолчала.

### 4.2. Средний приоритет

5. **Планировщик осторожнее.** Не смешивать похожие договоры в одном плане; при «аванс/гарантия + имя» якорить один документ.
6. **Гарантии без выдумок (#17).** Если в тексте «срок устанавливает производитель / талон» — запретить подставлять конкретный срок из воздуха.
7. **Метрика «как судья» локально.** Рубрика 18 демо vs `demo_output.csv` глазами + чеклист (прямой ответ, модальность, лимит, редакция, без лишнего). Эталон в индекс/промпт **не класть**.
8. **Следить, что все ID идут в `full`.** Если на платформе часть уходит в `fast`/`deadline` — балл упрётся в цитаты без вывода. Тогда крутить `MAX_WORKERS` / бюджеты, а не промпт.

### 4.3. Чего лучше не делать

- Новый полный second-pass на все ответы (паттерн v4 → регрессия).
- Снова включать реранкер «на всякий случай».
- Индексировать `demo_output.csv`.
- Гнать локальную Qwen как proxy LLM-судьи платформы.
- Рандомное да/нет при таймауте.

### 4.4. Ожидания по баллу

| Ориентир | За счёт чего |
|---|---|
| 29 → ~35–40 | детерминированные фиксы #5/#9/#11/#13/#17 + фильтр контекста |
| 40 → 60+ | меньше логических ошибок на **скрытой** выборке; поведение на модели организаторов; без логов платформы это уже медленная итерация «один рычаг — один сабмит» |

Правило сабмитов: **1 изменение → 1 загрузка**; падение > 0.5 → откат к текущему лучшему ZIP.
